# 第三方技术接入技能实施计划

用户已确认将官方依据优先的规则落实到 Uni Skills，并调整开发、库工程与设计入口，避免重复且保持独立可用。

## 范围与分工

- 新增 `uni-third-party-integration`：负责设计、接入、封装、升级评估与排障中的版本化官方依据、方案选择和验证边界。
- Uni RN／鸿蒙开发及库工程技能保留独立使用所需的简短要求，详细方法可选组合新技能，不依赖兄弟目录。
- Unif 架构源的依赖治理记录项目采用要求，开发与设计入口按任务读取本目录同源资料；通过已有生成器同步，不手改生成文件。
- 同步目录、插件描述和新技能的发现正例、反例及应用题。版本、发布、安装和现有业务实现不在本次范围。

## 实施与验证

- [x] 核对来源、授权、已有差异及同源生成范围；在仓库外保存初始快照和书面场景基线。
- [x] 新增技能、元数据与目录入口，合并现有重复指引。
- [x] 更新架构采用条款与相关技能入口，生成同源资料和五插件副本。
- [x] 检查格式、链接、独立包、题库与既有维护测试；定向复核设计、已发布修复、未发布修复和资料缺失场景。
- [x] 核对最终差异和原有工作，回填实际验证结论。

## 判定边界

重点检查版本不匹配的官方示例、已合并但未发布的修复、官方资料缺失，以及可选组合是否被误写为前置依赖。基线已满足项不算新增改善；书面场景、离线检查与真实宿主验证分别报告。

## 本地验证结论

Uni 131 项、Unif 188 项维护测试及 Uni 交付工具完整校验通过；Uni 8 个技能入口与格式、24 题题库，Unif 22 个技能与 73 题题库、11 项规范来源同步及五插件副本校验通过。新技能和四个关联 Uni 技能的本地引用及图标均位于各自目录。

同一组合题的四个场景，在现有 RN 入口与新技能独立入口的各一次书面作答中均满足判据；三项定向发现检查符合约束。样本有限，未证明正确率提升或真实宿主自动触发。独立静态审查指出的“先确认修复版本”前置歧义已改为核查是否发布，再按取得的依据处理。未运行远端模型评测、发布或安装；不涉及应用构建、设备或真实业务验收。
