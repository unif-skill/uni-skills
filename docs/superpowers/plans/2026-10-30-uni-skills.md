# 通用工程技能与 RN 文档迁移实施计划

> 执行入口：按 `superpowers:executing-plans` 逐项实施；独立技能验证采用 `superpowers:writing-skills`。按下列范围实施、验证并交付。

**目标：** 创建四个通用技能，迁移原规范并整理 11 个 RN 库的文档。

**结构：** 新插件维护通用规则，原规范保留项目专属内容，库文档描述自身能力；共享模板负责入口同步。

**技术：** Markdown、插件 JSON、技能 YAML，复用现有 Python 同步与验证及各库文档工具。

**设计：** [通用工程技能拆分设计](../specs/2026-10-30-uni-skills-design.md)。

## 共同约束

- 四个入口为 code-organization、react-native-development、react-native-library、documentation。
- 保留有效规则的校验、生命周期和契约同源要求；项目特例不能成为通用要求。
- 保留已有工作，不改运行时行为、依赖版本、历史计划、许可与署名。
- 交付通过各仓既有 PR、CI 和 main 合并流程，核对实际发布触发与文档部署；只清理本次已合并的分支和工作区。日志及原始评测放在仓库外。

## 审查重点

- 纯文档任务能单独使用文档规范；鸿蒙与脚本不进入 RN 流程。
- 已有项目约定、Schema 生成源及工具固定命名不被默认文件规则覆盖。
- 迁移后旧入口、测试与生成源没有失效引用或重复正文。
- 文案精简仍保留支持范围、安装条件、取消及资源处理语义。
- README、站点、包描述及生成资料使用当前接口，历史文件保持原意。
