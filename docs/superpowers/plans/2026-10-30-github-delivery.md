# GitHub 交付标准迁移实施计划

**目标：** 新增独立 github-delivery，将共享工程资源迁入技能，并使现有与未来 RN 库能独立运行已采用的 CI。

**设计：** [交付技能与标准来源迁移](../specs/2026-10-30-github-delivery.md)。

**实现：** 复用既有 Bash、Node.js、Python 同步与验证工具；生成仓内采用记录，不新增服务或依赖。

## 约束

Unif Dev 与 uni-skills 不相互依赖。保留实际消费者保护及历史记录，已有并行修改不纳入。现有库保留原发布配置与 PR 审查服务；新库仅按明确采用配置启用。远端写入、安装和发布另按授权执行。

## 任务

- [x] 核对旧标准源、实际 CI 消费者、组织绑定和基线回归；确认从实时标准改为仓内已提交版本。
- [x] 新建 skills/github-delivery 的入口、references、scripts、templates 和 UI 元数据，补充 README/评测。
- [x] 通用化目标身份与模板渲染；加入仓内采用记录及离线受管文件检查；保留原产物与发布校验。
- [x] 重构 Unif 技能为独立完整目录，新增企业组织配置，按 rn/harmony 及实际阶段从规范源生成所需资料；同步 1.0.0 版本与发布校验边界。
- [x] 更新 11 库的 workflow、交付检查与当前工程说明；保留各库特有文件与必要保护。
- [x] 执行新库、模板、发布与技能校验，独立审查后完成有依据的修复。

## 检查重点

1. 非 Unif 包名、任意合法 owner/repo、安装目录变化不破坏脚本。
2. 受管文件漂移、缺项和旧自动化仍使检查失败；`--check` 不写工作树。
3. 自定义文档 builder、受管块之外内容、构建接线、已有发布 App 和额外远端规则保留。
4. 私有技能仓不成为公开库 CI 的下载依赖；新库不自动调用 PR 模型服务。
5. 历史仓与线上仍在使用的流程保持可用，最终停用由实际交付证据决定。

## 本地验收

通用交付回归 153 项、远端配置模拟 27 项及 CI/LLM 原有契约检查通过；新增非 Unif 身份、组织配置、悬空链接和旧管理块迁移用例。Unif 分发、同步及版本回归 98 项通过，12 技能目录校验与六项规范同步通过。11 个实际消费库的离线检查、来源同步检查、actionlint 和差异检查通过。

独立上下文分别消费 code-testing、code-review、code-delivery 的完整目录，能读取自身必要资料并给出测试、鸿蒙资源审查和组织接入判断，无需兄弟技能或根维护工具。此结果不代表所有任务、宿主自动发现或真实业务已验证。

独立代码审查发现的三项边界缺陷均先复现，再修复并通过回归。源码与工作树迁移已完成；提交、推送、发布、安装和实际远端 CI 尚未执行。旧标准仓仍为已发布消费者保留运行入口，停用须在消费者交付后核对。
