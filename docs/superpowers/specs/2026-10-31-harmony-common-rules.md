# 鸿蒙通用规则提炼

## 目标与归属

新增可独立分发的 `harmonyos-development` 和 `harmonyos-library`，补齐原生 ArkTS／ArkUI 实现与 HAR 工程入口。技能适用于不同组织，不绑定最低 API、V1／V2 选型、固定厂商、业务目录或企业包名。

| 规则 | 维护位置 |
|---|---|
| 通用目录、文件角色、命名与边界 | 现有 code-organization |
| ArkUI 状态、宿主生命周期、Context、平台接入与资源交接 | harmonyos-development |
| HAR 公开入口、依赖资源、共享源、产物与独立宿主消费 | harmonyos-library |
| Unif API 26 采用、六库职责、身份与业务协议、视觉及提供方 | Unif 架构规范；Unif Dev 从规范源生成专题 |

技能按任务独立发现，不建立安装、调用或跨目录文件依赖。通用规则从原鸿蒙规范提炼，Unif 规范保留项目采用方式与有效业务契约；生成资料不手改。新增技能不启动鸿蒙产品实现。

## 验证依据

基线已有 code-organization 的异步隔离、公共入口与依赖图规则，不能将这些计为新增改善。缺口是独立原生开发入口、项目采用版本与状态机制的判断、宿主资源交接以及实际 HAR 的独立消费。

按[评测任务](../../../evals/cases.md)验证两个完整目录的隔离使用，检查非 Unif 工程、旧 SDK／V1、迟到结果、借用媒体与包产物消费。再核对 Unif 迁移前后约束、同源生成、既有脚本回归和安装发现。格式、行为应用、插件加载与真实产品运行分别记录。

## 实施顺序

1. 保留基线证据与现有有效约束，新增两个技能及必要资料。
2. 收拢 Unif 鸿蒙规范的项目采用内容，生成受影响开发、测试、审查和交付专题。
3. 检查隔离分发与迁移完整性，完成已授权交付并更新插件和共享技能入口。

过程输出保存在仓库外；发布与安装以实际回读结果为准。

## 本地验收结论

7 个通用技能目录、两个新增技能的隔离分发、UI 元数据和变更文档引用检查通过。独立消费任务能保留 API 13／V1，区分旧宿主结果与资源收尾，并为 HAR 识别实际归档及独立消费缺口；未要求其他技能或 Unif 选型。

迁移审查未发现有效契约遗漏或新增强制依赖。Unif 17 个独立目录、11 组同源检查及 101 项既有脚本回归通过。以上是技能内容与维护工具的证据，不表示鸿蒙产品构建、设备运行或业务验收完成。
