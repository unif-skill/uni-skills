# GitHub 交付技能与标准来源迁移

## 目标

在 uni-skills 中新增可独立分发的 github-delivery，集中维护 GitHub 工程交付指引及实际模板、检查和同步工具。新库和现有库使用同一来源；Unif Dev 保留企业契约，不要求调用或安装另一套技能。

## 采用方式

技能按任务描述发现。企业包名、Pages、发布 App 及仓库策略由 Unif Dev 的 code-delivery/assets/organization.json 单点维护，接入时复制到目标工程 .github/organization.json；通用工具只读工程配置。Unif 技能平铺且每个目录自含所需资料，共同规范由架构源生成，版本迁移至已明确授权的 1.0.0。GitHub 工程配置与操作方法属于 github-delivery；RN 能力和宿主契约属于库自身，通用文档与 RN 实现规范由各自技能维护。选择工程模板前检查实际技术栈与依赖；当前自带模板覆盖采用 Yarn、Turbo、release-it 的 RN 库，不自动给其他工程增加 RN、网站或外部审查服务。

消费仓提交生成的工作流、检查工具和 `.github/delivery.json` 采用记录。CI 校验仓库已提交的版本，不读取本机技能或私有技能仓。标准升级由技能同步到消费仓，再经 PR 验证；同一来源的生成产物不另行手工维护。

现有 PR 自动审查改为调用消费仓自己的 reusable workflow，保持事件、权限、模型配置及密钥契约。未采用该服务的新库不自动启用。现有发布身份、远端保护、包名、网站与项目专用构建保留；通用模板不包含某个组织的 App ID 或个人联系方式。

## 迁移与保护

- 来源迁移覆盖规则、执行脚本、模板、生成检查和实际引用；不只增加 SKILL.md。
- 保留包身份、产物路径、符号链接、exports/types、发布恢复、受管区块、模板漂移和取消保护。
- Unif 技能的生成主题从架构源修改后同步；历史设计、计划、验收保留。已有 STATUS.md 修改不属于本次。
- 旧标准仓在仍有远端消费者时保留运行资源；停止重复维护新规则。停用旧仓须在消费者交付并核对后处理。
- 本次实施和本地验证不自动授权提交、推送、发布、远端权限调整或付费服务调用。

## 验证

验证独立技能目录、非 Unif 新库、JS/原生/站点组合、二次同步与只读检查、局部漂移和已停用配置。执行迁移工具现有回归与 actionlint，核对 11 个 RN 库的实际 CI、项目专用文件及本地采用记录。源码、工具测试、模型使用、本机安装、远端 CI 与发布分别报告。
