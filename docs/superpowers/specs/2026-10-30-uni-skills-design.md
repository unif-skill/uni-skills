# 通用工程技能拆分设计

## 目标与边界

建立独立于企业和应用的 `uni-skills`，包含四个可按任务使用的技能。提炼现有 React Native 工程规范，统一各种技术文档的编写要求，并用已有 RN 库的文档维护检验规则。

| 技能 | 职责 |
|---|---|
| code-organization | 前端、RN、鸿蒙等工程的目录、文件角色、命名与公共出口，遵守各语言及工具的实际差异 |
| react-native-development | RN 组件、Hook、样式、交互状态及原生接入，独立维护框架实现规则 |
| react-native-library | RN 库创建、维护、验证、分发、发布及运行示例；从目标项目取得实际模板、CI 和发布标准 |
| documentation | 所有工程的文档编写、重构与审校，以及文档站、导航、生成与构建，包括 RN、鸿蒙、脚本及项目说明 |

通用技能不依赖 Unif、Portal、固定包名、个人路径或某个组织的发布服务。项目已有有效约定优先；没有约定时使用技能给出的默认组织方式。技能不因被加载而新增发布、远端配置或运行时依赖。

## 方案

采用独立插件、按职责划分四个技能的方案。每个技能的核心规则和必要资料放在自身目录，可单独使用；任务确实跨越职责且对应技能可用时再组合。相比单个综合入口，这种方式能让纯文档、代码组织、RN 实现和库工程分别进入自己的规则。源码采用标准插件的 skills/ 目录，技能名称不加仓库前缀，不增加 RN 分类层。

## 规则归属与迁移

- 通用规则在新技能维护，项目规范保留技术选型、业务目录、系统边界和所属契约。
- 现有 Unif 技能中的手工库开发、新库接入、文档站资料迁移后更新全部当前引用，不保留同一职责的两套正文。
- RN 文件规范的生成资料从架构源修改后重新同步，保留生成溯源、覆盖检查和 Portal 专属约定。
- `.github` 保留实际模板、校验脚本、CI 和发布标准；共享 Agent 模板引用新技能，现有 API 能力技能继续提供各库契约。
- 已有未提交 README 规则调整作为待迁移内容保留意图；其他未提交工作不修改。

## 文档整理

覆盖当前 11 个 `react-native-*` 库的 README、使用与 API 文档、开发及脚本说明、Agent 入口，以及包描述、网站描述和首页介绍。逐项判断实际问题，不为形成差异改写已有准确内容。

按读者要完成的操作组织内容，直接说明用途、输入和结果；同类要求与对照优先表格，操作使用步骤，调用使用最小示例，复杂细节链接所属指南；保留必要前提、默认行为、错误、取消、平台差异及资源处理要求。区分支持范围和实际验证环境。已有文档生成链修改来源再生成，不手改生成产物。

保留项目计划、设计方案、有效契约和必要验收结论。保护自动更新的 CHANGELOG、许可证与署名；不把历史记录重写为当前事实。文案与引用调整不改变 API、组件交互、依赖版本或发布流程。

## 验证

技能格式、引用和插件清单检查；独立任务的无新技能基线与采用候选对照；现有技能生成检查及测试；共享 Agent 模板回归；各库文档生成、类型或构建检查按实际输入执行。实际使用任务用于检查规则是否易于发现、是否造成误路由或企业绑定，不将静态校验当作模型行为证明。

源码、测试、文档构建、页面检查和安装发现分别报告。交付包含源码创建与迁移、文档优化、按各仓既有流程提交和合入 main、文档发布及本次分支清理。合并前识别实际发布触发，库包与文档站分别核验；版本遵循既有规则，主版本保持。仓库可见性、应用部署和无关分支不在本次范围。
