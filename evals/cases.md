# 技能应用与独立使用

在独立上下文给出实际任务及其原始资料；候选对照使用同一任务，仅改变技能是否可用。评审实际文件组织、文稿和行为，不以出现某个关键词作为通过证据。基线已满足项不计为新增改善。

| 技能 | 任务 | 核对结果 |
|---|---|---|
| code-organization | 新 RN 应用新增有 props、命名阈值、样式和实例计时器的私有组件；再考虑项目已采用其他命名、类型已有 Schema 源两种变体 | 文件角色明确，实例资源保持作用域，遵守已有命名，类型不重复定义，不预建无用目录 |
| react-native-development | 实现受控输入，异步操作在卸载或目标切换后结束，应用已有 UI 宿主与原生依赖 | 保持受控状态与生命周期，旧结果不污染新实例，沿用真实宿主并按平台验证 |
| react-native-library | TS 库调用现有原生 SDK，应用已有补丁、项目有统一模板与 website，只交付本地候选；注册表超时且有历史版本 | 库模板与真实原生宿主分别处理；沿用补丁归属和工程来源；验证实际 tarball；不自行发布、复用历史版本或转移补丁分发 |
| github-delivery | 仅提供完整技能目录，为非 Unif 新 RN 库接入 CI；再迁移有组织配置、项目专有 CI 和自有 LLM builder 的现有库 | 不依赖其他技能或旧标准仓；保留组织校验、项目差异、漂移门禁、发布身份与安全边界；新库不自动启用模型服务，CI 运行已提交版本 |
| documentation | 改写 RN 接入 README、鸿蒙库介绍和清理脚本说明，材料含取消、文件释放、支持范围、补丁、异常及删除开关 | 表达直接，各类文档采用合适结构；条件和错误语义保留，示例不补造接口，鸿蒙与脚本不进入 RN 流程 |

代码组织另外检查文件路由、Vue 单文件组件及鸿蒙固定入口，避免套用 RN 文件集合。

RN 文档样本明确提供依赖支持范围与验证环境，分别核对；脚本样本包含默认预览和显式删除，检查退出码与部分失败。资料缺少导入或返回类型时，输出标为片段或进一步核对，不能编造可运行示例。

## 单目录分发

每次将一个完整技能目录复制到仓库外，独立核对 SKILL、引用资料和 UI 元数据。相对资料不能越过该技能目录；若使用其它技能，必须是明确可选的任务组合。独立任务可以只获得这一个技能，其核心工作仍应完成。

## 项目采用

在真实工程中检查技能发现、规则来源、授权范围、文案准确性及必要构建。共享规则迁移后核对旧入口与实际消费者，避免只验证新文本自身。格式、静态引用、模型应用、工具加载和真实工程验证分别记录。

## README 阅读与信息呈现

给出含多项依赖版本、验证环境、平台差异、完整配置和长 API 枚举的真实 README，让被测者在保留必要使用条件的前提下整理。检查其能否按信息关系选择表格、步骤、列表和代码，清楚区分支持范围与验证环境，并将详细操作归入现有指南。不能只缩短句子、机械把所有内容表格化，或删除关键限制。以实际文稿及宽窄屏呈现核对，不设统一字数和行数门槛。
