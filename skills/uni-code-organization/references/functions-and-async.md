# 函数与异步流程

先核对有效契约、真实调用方及当前调用轨迹，再调整函数边界。抽取职责应减少调用者需要同时理解的概念；输入、输出、副作用和资源责任仍可追溯，不把一个流程拆成只转交参数的多层接口。

## 表达真实依赖

在支持 async/await 的语言中，用它清楚表达需要等待的操作和实际先后依赖；同步校验、纯计算和同步能力保持同步，不为统一写法增加 async、Promise 包装或无意义 await。保持同步校验的入口可以先校验，再返回现有异步操作；不要把校验搬入 async 函数而悄悄改变错误通道。

先判断数据依赖、请求顺序、共享状态、限流和服务约束。互不依赖且契约允许并行的任务一起启动并汇合结果，不因逐项 await 无意串行化；依赖前一步结果或要求顺序的写入继续串行。调整既有流程的并行度前须证明其对外契约允许，不能把“数据独立”当成副作用也独立。并行失败时按任务要求选择整体失败或收集各项结果，并处理已经启动的任务；聚合 Promise 拒绝不代表其余工作自动取消。

## 重构保持契约

比较修改前后的真实消费者与关键轨迹，必要时用事件记录或行为测试核对：

- 返回值及同步返回／异步完成边界；同步抛错与 Promise 拒绝分别如何被调用方捕获，错误是否被吞掉或替换。
- 校验、请求启动、事件、状态提交及其他副作用的先后关系；失败后哪些操作原本不会发生。
- 取消等待、底层停止、结果接受和资源可释放的条件；不能以等待结束替代底层收尾。
- 每轮操作与发起实例、目标及身份的关联；取消、卸载、目标或身份变化后，迟到结果与旧轮清理不能修改新实例或释放新资源。
- 资源所有权与清理责任；保留成功、失败、取消和重复／迟到收尾的必要保护，不删除借用或已交付的资源。

只验证最终成功值不足以证明重构等价。按本次影响覆盖同步失败、异步失败、允许并行的启动关系、顺序副作用及相关取消/迟到轨迹；语言和框架特有生命周期再从目标工程核实。

## 语言依据

上述同步/异步与拆分取舍是本技能的工程建议，不要求所有语言使用 JavaScript 语法。JavaScript 的 async 函数体抛错会用于拒绝返回的 Promise，见 [ECMAScript AsyncBlockStart](https://tc39.es/ecma262/multipage/control-abstraction-objects.html#sec-asyncblockstart)；同步函数改为 async 并非仅改变书写形式。其他语言按采用版本的语言规范及实际运行时确认错误和调度语义。
