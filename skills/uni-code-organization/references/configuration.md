# 配置文件与环境变体

适用于新增、调整或审查 `.env`、环境变体及其加载入口。先读取项目对配置归属、模板和运行方式的约定；其他格式按所属工具的配置结构处理，不强套 dotenv 规则。

## 归属与加载

先核对现有配置文件、对应模板、启动命令以及加载和覆盖顺序。共享配置、服务专有配置和本机工具配置保持原有职责；环境变体沿用所属配置的层级，不因名称包含 `debug`、`local` 或 `test` 就移到项目根目录。

同一用途优先复用项目已采用的环境文件及加载入口。更换操作者、设备或临时调试地址，不单独构成新增完整配置副本的理由；一次性设备参数沿用已有启动参数或仓库外个人配置。任务或有效契约明确要求独立环境时，再按实际差异和消费者新增变体，不把开发、测试、正式环境强行合并。

确认项目采用完整环境文件还是差异覆盖。完整配置不能自行缩成少数覆盖项；工程明确采用差异覆盖时，不反过来强制复制全部变量。新增文件必须接入实际启动入口，避免文件已写好、进程仍加载原配置。

## 内容与排列

完整环境文件按所属模板核对变量集合和顺序，并沿用已确认环境文件的分组、注释层级、空行及必要格式。只替换本环境确实不同的值，相同配置从已有有效环境补齐；不重排成个人偏好的分类，也不把所有配置混进一个文件。

模板中的地址、凭据和数值可能只是示例。缺项先核实有效默认值或配置来源，保留当前行为；不能直接复制占位值，或把示例数值当成当前运行值。已有自定义参数按其有效契约保留，同步所属模板，不以减少配置项为由删除。

实际值和敏感凭据留在项目允许的本地文件或密钥来源中；模板只保留安全示例。沿用忽略规则和文件权限，检查输出不展示原始配置值。

## 验证

合并或移除重复配置时，先比较实际差异并确定采用的环境，不将旧副本的服务地址或凭据自动覆盖到保留文件；迁移启动参数、加载副本及临时文件选择，确认没有有效消费者后再删除。历史构建记录保留当时使用的文件信息。

核对变量缺失、重复、多余、顺序和分组排版。完整 dotenv 文件可运行随技能提供的只读检查：

```sh
python3 scripts/check_env_shape.py /project/service/.env.example /project/service/.env.debug \
  --layout-from /project/service/.env
```

脚本路径相对本技能目录。`--layout-from` 指向已经核对的环境文件；只有模板时可省略，随后人工核对分组。脚本支持引号包裹的多行值，不执行变量展开，只报告键名和结构差异；不用于判断地址、凭据或业务参数是否正确，也不用于项目明确采用的稀疏覆盖文件。

再通过启动器的配置解析或进程的安全诊断核实实际生效值、依赖地址和环境隔离。必要时重建或重启受影响进程；是否执行仍遵循用户授权。分别报告文件对齐、加载核对和实际运行验证，不能以结构检查通过代替环境已切换。
