# 平台与工具边界

组织原则通用，目录、扩展名和文件角色采用当前语言、框架及工具的实际约定。先读工程入口、manifest、编译和路由配置，再应用默认命名。

## 前端

文件路由、页面入口、服务端与客户端边界、资源导入和 CSS 处理按实际框架组织。框架保留名称不能因组件命名规则改写；增加路径别名须覆盖真实构建和测试入口。

React 的 TSX 组件可按职责分出类型、固定值与样式。Vue、Svelte 等单文件组件保留框架的模板、逻辑和样式结构，存在独立维护或共享需要时再拆。浏览器与服务端的运行环境分别核对。

## React Native

组件及 JSX 使用当前工程的 .tsx/.jsx 入口。Metro 的 .native、.ios、.android、.web 等解析方式按目标配置核对；只有真实平台差异时才新增实现文件。

样式文件维护 RN 样式及主题工厂，运行期参数由调用处传入。应用入口、原生工程、权限、Pods/Gradle 与库公开出口沿用其工具约定，不为目录统一复制原生配置。

## 鸿蒙

按当前 ArkTS 编译器与工程配置使用 .ets/.ts、模块、资源和构建文件。保留 Index.ets、module.json5、oh-package.json5 等实际固定入口及工具目录；HAR 的公开范围由包清单和真实导出共同确定。

组件、状态、操作和必要类型在所属单元内维护，有内容和独立维护需要时再拆。ArkUI 样式与资源、状态装饰器和 Context 遵守原生规则，不照搬 React Hook、StyleSheet、types.ts/styles.ts 的固定文件集合或 TypeScript 不受支持的推导语法。

跨平台共享先核对完整运行和类型依赖，按实际目标生成或构建。改后缀、没有框架 import 或 Node 测试通过，不能证明已经能被鸿蒙消费。

## 脚本与其他语言

命名、模块和导出使用该语言及工程已采用的规则；不强制 JavaScript 的 camelCase、interface 或组件目录。小型工具可保持单文件，出现真实维护边界时再拆。

配置、补充声明和生成文件保持工具固定名称。修改生成源后重新生成，不手改输出；测试按实际语言和目标运行环境执行。
