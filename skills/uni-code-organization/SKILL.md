# 代码组织与实现规范

适用于所有代码开发、维护和审查工作。遵循明确需求和已有约定，保留未要求改变的行为；语言、框架和构建工具的具体要求从当前项目取得。

## 调整依据与确认

开始或接续任务时，核对最新目标、有效契约、明确排除项和已撤回意见。对用户、评审者或自己提出的改法，区分目标、具体做法与事实前提；承诺实施前沿相关入口核查原行为的用途、状态归属、实际消费者及影响。复用仍有效的证据，只补本次变化涉及的部分；能从代码、契约或日志查明的事实自行核实。

发现尚未确认的事实偏差、目标不符或其他有效行为受影响时，说明具体依据、后果和需要用户决定的取舍，先请用户确认该部分。可以给出建议，不替用户选定、不先改后问，也不把技术偏好当作拒绝理由。用户了解影响后明确确认变更，就按新决定推进并更新相关契约和验证，不再用旧决定反复确认；不依赖该决定的工作继续。

依据充分且没有实质疑点的修改直接在授权内执行；纯偏好和已有契约下的等价调整不追加确认或完整设计流程。现有代码不自动构成保留理由，删除或替换按有效需求、消费者及数据保护依据判断。保留未要求改变的行为和已有工作区修改，来源不明的差异先核对归属。

## 基本要求

1. **分清职责。** 不同职责合理拆分，相关逻辑放在一起。名称说明用途，参数只传实际需要的内容。
2. **写清判断。** 合并重复条件，减少多层 `if` 和嵌套三元表达式。合理使用提前返回、`switch` 或函数拆分，保留各阶段必要的校验。
3. **合理复用。** 相同功能和规则统一维护，业务含义不同的逻辑分别保留。公共能力不依赖具体使用者，第三方接口和 SDK 的细节由接入代码处理。
4. **明确类型。** 写清每种状态允许哪些字段，让类型检查拦住错误组合。复用已有公共类型和 Schema，保留外部数据校验。
5. **管好异步操作。** 结果和清理绑定所属实例、身份与操作；失效操作不能影响仍有效的操作，取消不能覆盖已交付的成功。多个仍有效的操作按既有契约各自完成，不默认后发替代先发。处理好重复调用和资源清理，调整异步写法时检查执行顺序。
6. **正确处理错误。** 按约定交付失败、取消和异常，区分核心操作与附属处理的结果，按实际影响决定阻断、提示和恢复。出错后完成必要清理，避免一直等待；按实际失败边界保留可定位一次问题的证据，记录与不记录的条件见[错误与诊断](references/functions-and-async.md#错误与诊断)，诊断失败不影响原流程。
7. **补齐必要注释。** 新增和修改代码时，说明重要函数的用途、使用限制，以及谁负责创建和清理资源。关键判断和异步逻辑说明为什么这样处理，注释随代码同步更新。
8. **按改动范围验证。** 检查功能是否符合需求、相关调用是否仍然正确，覆盖受影响的异常和边界。修复先复现，重构对比前后行为；说明验证结果和未验证项。

## 执行范围

按已确认的场景、入口和对外行为界定授权。共用代码、局部反馈、审查建议和笼统的继续指令不扩大授权。授权内的必要调整直接推进，动手前简述拟改位置、行为变化和影响入口。需要改变范围外的行为或调用，或新增范围外的服务、权限或部署依赖时，说明影响并取得明确确认，同时继续推进不依赖该决定的工作。只读审查不自动修改代码。

依据已核实的能力与消费者选择复用、原处扩展或替换，说明实际缺口。名称相似不代表可以复用，未找到同名文件也不代表能力缺失。共享问题在所属实现修复，保留业务、平台和实例差异；有真实共用需要时才增加公共入口。

文件按用途组织，沿用项目命名、生成来源及工具固定入口。实例状态和资源保持原作用域，私有实现保持私有。替换后迁移相关调用、类型、测试、配置和文档，确认无消费者后清理失效实现、参数及分支。兼容、迁移和回退以有效契约、实际消费者或数据安全为依据。

按影响选择编译、lint、测试或运行验证，并检查相关路由、动态注册、生成器及平台入口。按需求和有效契约验收，核对权限、身份隔离和数据保护仍然有效。文件存在或编译成功不代表功能已验收。
