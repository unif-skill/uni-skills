# 代码组织与实现规范

适用于代码开发、维护和审查。需求、有效契约和授权范围决定变更边界；语言、框架与构建工具遵循项目采用的规范。

## 调整依据与确认

变更依据应包含目标、有效契约、排除项与授权范围。只读调查和审查交付事实与发现；实施变更须有明确授权。每处修改对应一项需求或既有行为的回归保护，技术优化、测试结果及评审建议不构成新增授权。

沿实际入口核对行为用途、状态归属、消费者及依赖，确认目标是否已由现有路径满足。已有能力满足需求时直接复用；存在缺口时，优先在所属实现扩展，再根据职责决定新增或替换。代码、契约和日志构成事实依据；推断应标明证据缺口，既有证据仅在版本和适用条件仍一致时复用。

新增兼容、迁移分支、交互步骤、业务规则或其他范围外行为，须在实施前取得包含方案、依据与影响的明确授权。技能、计划、评审结论、回归保护及事后记录不能替代授权。已获批准的行为变更、范围内实现细节和契约等价调整直接执行，相关契约与验证同步更新。待批准事项仅阻塞依赖它的工作，独立且已授权的部分继续推进；无答复或等待超时不构成批准，未完成范围须明确列出。

缺陷按根因归属修复：自有库负责库内缺陷，宿主负责接线问题。已授权修复可以跨仓实施，功能和行为范围保持原授权。库修复版本发布后，消费方升级依赖并复验原场景；发布和升级分别核对操作授权。

以实施前的工作区差异为基线，保留既有修改并核对来源不明的差异。交付审查逐项对应需求或回归保护依据，移除实施期间引入的越界修改，保留范围外原有行为与数据。

## 替换与清理

字段、接口和状态的保留依据是有效契约、实际消费者与数据保护责任。退役分析覆盖生产写入、读取、动态注册、外部消费者及保存恢复；单层输出变化、文本搜索无命中或仅有测试引用不能单独证明无消费者。有效消费者须先迁移并验证原行为；兼容实现按明确的支持范围保留，已明确取消的兼容范围不新增或恢复处理入口。

在授权范围内，同步核对并清理失效的协议源、类型与校验器等生成产物、调用与导出、配置、持久化及恢复处理、测试和文档。生成内容从所属源修改后重新生成。清理数据库相关实现时，还要核对建表源、初始化 SQL、迁移入口及专属结构测试；代码不再读写，不代表新库初始化已停止创建旧表或字段。

移除新库定义与修改现有数据库是两项操作。清理源码不自动授权执行删表、删字段或历史数据迁移；存量处理须核实数据与消费者，并按明确的数据处置授权执行。完成说明逐项区分已清理、仍保留的依据和未验证范围，测试通过不等于已排除所有残留。

## 基本要求

1. **分清职责。** 不同职责合理拆分，相关逻辑放在一起。名称说明用途，参数只传实际需要的内容。
2. **写清判断。** 合并重复条件，减少多层 `if` 和嵌套三元表达式。合理使用提前返回、`switch` 或函数拆分，保留各阶段必要的校验。
3. **合理复用。** 相同功能和规则统一维护。提取公共入口前核对业务、平台和实例差异，私有实现留在所属模块。公共能力不依赖具体使用者，第三方接口和 SDK 的细节由接入代码处理。
4. **明确类型。** 写清每种状态允许哪些字段，让类型检查拦住错误组合。复用已有公共类型和 Schema，保留外部数据校验。
5. **管好异步操作。** 结果和清理绑定所属实例、身份与操作；失效操作不能影响仍有效的操作，取消不能覆盖已交付的成功。多个仍有效的操作按既有契约各自完成，不默认后发替代先发。处理好重复调用和资源清理，调整异步写法时检查执行顺序。
6. **正确处理错误。** 按约定交付失败、取消和异常，区分核心操作与附属处理的结果，按实际影响决定阻断、提示和恢复。出错后完成必要清理，避免一直等待；按实际失败边界保留可定位一次问题的证据，记录与不记录的条件见[错误与诊断](references/functions-and-async.md#错误与诊断)，诊断失败不影响原流程。
7. **补齐必要注释。** 新增和修改代码时，说明重要函数的用途、使用限制，以及谁负责创建和清理资源。关键判断和异步逻辑说明为什么这样处理，注释随代码同步更新。
8. **按改动范围验证。** 根据本次改动和工程采用的规范确定验收项，从项目已有脚本或 CI 配置核对执行入口。使用项目指定的解释器、依赖和配置执行本地应完成的检查。Python 类型检查逐项处理检查范围内的错误与警告，不以降低诊断级别、关闭规则或新增忽略代替修复。工具缺失或启动失败时，核对解释器、依赖和执行目录，纠正后重跑；仍无法完成的检查说明缺项及影响。检查功能是否符合需求、相关调用是否仍然正确，覆盖受影响的异常和边界。修复先复现，重构对比前后行为，同时核对受影响的动态注册、路由、生成入口及权限、身份与数据保护。分别报告静态检查、运行验证和未验证项。
