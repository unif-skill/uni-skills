# 目录与职责

先读取项目实际入口和约定。已有 features、screens 或文件路由结构时，在其职责边界内新增内容；不为使用本参考改造目录。库、前端应用、鸿蒙模块和脚本分别沿用自己的入口、构建和资源约定，不因共享组织原则使用同一目录模板。

平台和工具的固定入口先见[平台与工具边界](platforms.md)。

## 应用目录参考

没有既有约定的新应用，可按以下职责选择实际需要的目录。业务功能可按工程采用方式放在 features 或 domains，不同时建立两套同义层次；没有实现的目录不预建。

| 职责 | 参考位置 | 边界 |
|---|---|---|
| 启动、导航与应用组装 | app | 连接真实依赖和必要宿主，下层不反向依赖启动代码 |
| 业务功能、页面和场景组合 | features 或 domains | 每个功能维护自身状态、流程、交互与接入 |
| 跨功能展示和交互组件 | components | 通过 props 与事件工作，不读取具体业务 store |
| 框架生命周期与可复用交互封装 | hooks、composables 或项目对应目录 | 按框架命名；功能专用封装留在功能内 |
| 设备、本地存取等能力 | capabilities 或项目对应目录 | 明确输入输出、副作用、平台差异和释放责任 |
| 外部系统与协议适配 | integrations 或项目对应目录 | 维护原始 DTO、请求转换与接入错误 |
| 无业务状态的计算与格式处理 | utils | 不隐藏网络、设备或持久存储操作 |
| 构建环境和应用配置 | config | 组装处读取并传入必要字段，不保存业务状态 |
| 共用静态资源 | assets | 专属资源优先随功能；主题由设计系统维护 |
| 必要的环境或第三方补充声明 | types | 不集中存放所有业务模型或组件 props |
| 工程工具和原生接入 | scripts、ios、android | 遵守当前工具和平台约定 |

页面与自己的类型、样式、hook 构成单元。私有子组件留在页面内；跨页面、同功能的组件放功能内部；存在真实跨功能消费者时才提升为公共组件。文件角色见[文件与命名](file-rules.md)。

模块的固定值、业务文案、数据库结构和接口路径随所属功能维护，不形成全应用常量或类型总仓库。测试按现有相邻测试或镜像目录定位；共用 fixture 和辅助只有实际复用时才集中。

## 拆分粒度

按职责和实际变化需要划分函数与模块。连贯的小流程可以放在一起；拆出后应能清楚命名，并说明它负责什么。行数、文件数或调用层数只用于提示检查，不作为拆分标准。

提取逻辑应让调用者更容易理解，避免多层只转交参数的包装、重复接口或同一状态的多份副本。已有结构合理时沿用，确需调整时保留原状态和资源责任。涉及调用顺序时读[函数与异步流程](functions-and-async.md)。

## 依赖与状态

应用组装调用公开功能并提供配置；场景组合协调已确认的操作；独立功能只依赖其契约、必要 SDK 和公共支撑。设备与协议层不反向读取页面或业务场景。两个功能协作时，由场景负责顺序，不互相驱动对方状态。

组件和通用生命周期封装可维护光标、展开等局部 UI 状态，业务草稿和最终结果由实际场景持有。共享 UI 不要求共享业务状态。只有实际消费者需要时才定义公共展示类型，避免从领域私有对象中取类型穿透边界。

按用途、所有者、使用者和有效期确定状态的保存范围，仅持久化具有明确恢复需求的数据。临时交互与可重新取得的数据按实际需要管理，不因同处一个对象就一并保存；收窄范围时保留必要的请求关联、已确认事实和数据完整性校验，已有持久数据按有效恢复契约处理。

状态发布、订阅、派生计算和保存触发围绕实际读写关系组织。局部变化只通知真正依赖它的消费者并执行必要保存，跨功能的有效更新继续传递；合并通知或延迟保存须保留执行顺序和关键保存屏障，不能用统一去抖掩盖职责耦合。

局部界面调整先核对现有主题、样式和配置，结构存在问题或无法满足需求时再调整。用布局、层级和分组表达信息与操作关系，保留必要的操作提示、状态反馈和无障碍语义。

身份、客户端或原生能力用普通参数、小型依赖对象或已有适配接入，只传所需能力和字段。项目没有实际需要时不增加容器、事件总线或注册中心。已有 SDK 的类型与功能直接使用，接入代码处理真实协议差异、异常分类和资源交接，不复制 SDK 内部实现。

相同功能和默认规则维护一处，各调用方保留自己的业务结果和交互。复用前核对完整语义、版本、平台、宿主与组合约束，单个入口正常不证明其他组合适用。共享能力不反向读取具体页面、业务状态或调用方私有类型；沿用已有共同契约，没有共同契约时由所属能力定义自身语义。

取消、卸载、目标切换和身份失效按实际操作清理订阅与资源，旧操作结果不能修改新实例。组件拆分检查真实状态订阅、交互和事件，不以文件数量或 render 次数代替行为验证。

## 配置与新增检查

依赖、锁文件、编译、模块别名和测试解析使用当前工程配置；新增别名须覆盖其真实消费者。只添加实际运行或构建所需的依赖，版本范围按项目约定，不将当前开发版本自动写成所有消费者的最低要求。

新增单元核对其调用入口、数据与副作用、依赖方向、资源结束及必要测试。迁移单元时同时核对路由、动态注册和生成工具等非普通导入关系。自动规则优先使用现有 TypeScript、ESLint 和适用静态分析，语义判断仍以需求及契约为准。
