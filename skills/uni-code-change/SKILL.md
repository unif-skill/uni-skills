# 实现、重构与清理代码

从用户确认的行为、有效契约和本次允许修改的范围开始。记录起始工作区差异，沿实际入口找到实现、消费者、状态所有者和测试。已有路径满足目标时给出位置和证据。存在缺口时，先考虑复用或扩展负责这项行为的实现。语言、工具链与外部契约按目标项目采用的版本核对。

职责转移或字段含义变化时，即使字段名和类型未变，也要用同一份输入说明变更前后分别由谁、按什么条件判断，结果交给谁。用新旧两种说法反查现行契约、模块说明和实际调用，包括差异之外的文件及已改文档中相邻的未改段落。在授权范围内纠正仍把旧规则当作现状的说明，历史记录保留当时的结论。

## 实施变更

1. **确定改动落点。** 列清本次需要变化的输入、结果或副作用，以及消费者仍依赖的行为。项目已有公开类型、Schema、依赖注入入口或扩展点时沿用。共享能力只接收所需参数并保持依赖方向，第三方细节留在接入层。
2. **保持状态和时序。** 用类型表达各状态允许的字段，保留外部校验。集中相同的默认值和失败规则，保留异步等待前后各自必要的检查。结果、取消、监听和清理绑定原身份、操作与资源所有者。按契约处理并存操作、乱序或迟到回执，取消保留已交付的成功。
3. **处理失败。** 区分核心操作和附属处理，根据影响决定阻断、提示与恢复。异常路径完成必要收尾，保留能解释一次失败的安全证据。关键函数、资源交接和时序判断旁写明类型和名称无法表达的原因。细节见[函数与异步流程](references/functions-and-async.md)。
4. **核对作用范围。** 新增兼容、交互、业务规则、迁移分支或其他范围外行为前，说明具体方案、依据与影响，取得对应授权。范围内实现细节、已确认的变更和契约等价调整可以直接执行。待确认只阻塞依赖该决定的工作。评审建议、计划、通过的测试和等待超时均不能代替授权。
5. **验证实际入口。** 使用项目采用的工具、依赖和配置执行相关检查。修复用原复现验证，重构对照相同输入的结果与副作用。检查受影响的调用、动态注册、权限、身份和数据保护。按起始差异逐项回看本次修改，保留他人已有工作，撤回本次引入的越界内容。分别交代已实现行为、验证结果和未覆盖范围。

修复归属按根因决定。自有库处理库内缺陷，宿主处理接线。已授权的修复可以跨受影响仓实施；发版与消费方升级分别按其授权进行，按消费方实际解析的修复版本复验原场景。

## 清理字段、接口或存储

- 先确认有效契约、版本和数据保护责任，追踪生产写入、读取、动态注册、外部消费及保存恢复。单层输出变化、搜索无命中或仅剩测试引用都不足以证明可以删除。仍有消费者时先迁移，验证其原行为。明确退役的输入不恢复兼容入口。
- 在批准范围内，核对协议源、生成类型和校验器、调用与导出、配置、持久化与恢复、测试及文档。生成内容从维护源修改并重新生成。涉及数据库时还查建表源、初始化 SQL、迁移入口和专属结构测试。
- 从新库定义移除字段与处置存量数据分别核实。现有数据库的删表、删字段和历史数据迁移须有相应数据处置授权。交付时说明已清理范围、仍保留的消费者或数据依据和待验证项。
