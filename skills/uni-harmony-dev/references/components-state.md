# 组件、状态与生命周期

## 状态与输入

新建 ArkUI 状态采用 API 26 支持的 V2 机制，装饰器与组件交互按对应 SDK 的官方约束核对。观测能力不改变状态所有权；修改现有调用方仍遵守本次范围，不为局部任务重写无关组件。

组件接收公开输入、事件与明确依赖。受控值由调用方负责，组件短暂交互状态留在组件；派生显示不再维护一份可独立变化的业务状态。业务记录、持久化与恢复由实际拥有者处理，库不读取应用私有路由、store 或凭据。

## 宿主与操作

分别识别组件／页面实例、UIAbility、WindowStage 和实际操作的存活范围。它们的生命周期不是同一条时间线；组件离开、窗口失焦、应用进入后台和操作完成分别按所采用 API 与契约处理。

异步结果返回时核对发起操作、当前目标及拥有它的实例是否仍有效。页面重建、相同标识重新出现或新的宿主创建，都不能重新激活旧操作。事件监听、计时器、观察和原生会话按所属范围注销或结束，迟到回调不得更新新页面、触发新操作或释放新实例的资源。

离开页面不自动删除业务草稿、上传中的文件或已经交付的结果。UI 销毁、后台暂停、恢复和业务取消由有效契约分别决定；资源交接同时参照[平台接入](platform-integration.md)。

## 主题与界面

先用已有组件、资源和组合能力完成交互，再补实际缺口。颜色、字体层次、尺寸与图标沿用设计源，平台资源和单位按当前工程映射；避免系统与自有逻辑重复缩放字体。

响应式布局依据实际窗口、可用区域和输入方式，不能只按设备名称判断。保持可点击范围、焦点、无障碍语义和内容可读性；在任务涉及的窗口、主题、字体及键盘条件下核对遮挡、截断和状态变化。

系统材质、普通模糊与透明背景分别处理。不支持的表面按项目已确认的视觉及可操作性处理，不通过移动入口、添加权限或更换框架制造效果。

## API 26 系统材质

采用沉浸光感时，区分组件级 `systemMaterial`、弹窗选项、组件专属接口与应用级配置，并按下表核对支持条件和实际效果。

| 核对项 | 平台要求 |
|---|---|
| SDK 与应用配置 | target 至少为 26.0.0；`ohos.arkui.UIMaterial.state` 应用级元数据只在 entry 模块生效，HAR 不能替消费应用开启全局配置 |
| 组件所在区域 | 指定弹窗／菜单等接口及 Slider、Toggle、Select 可在全页面生效；其他组件限官方列明的 Navigation／NavDestination 标题栏、横向 Tabs 底部 TabBar 等区域，不能将普通自定义卡片视为受支持载体 |
| 运行条件 | 核对设备支持、材质等级与系统效果设置；按 SDK 实际提供的 uiMaterial 查询及组件接口确认运行状态 |
| 验证方式 | 分别验证组件入口、宿主配置和真实运行效果；项目决定表面映射及不支持时的视觉表现 |

版本依据：[沉浸光感与设备／系统设置](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/arkts-immersive-light-sense-overview)、[开启入口与支持范围](https://developer.huawei.com/consumer/cn/doc/HarmonyOS-Guides/arkts-immersive-light-sense-enable)。具体签名、载体和限制以 API 26 SDK 与对应官方资料核实。

## 验证

按公开输入与事件验证状态变化，再在真实调用方核对接线。与本次变更相关时覆盖连续触发、目标切换、页面／Ability 重建、前后台、取消及迟到结果；不把替身模拟生命周期当成真实宿主运行证据。界面对照使用相同数据和环境，记录平台差异及未覆盖条件。
