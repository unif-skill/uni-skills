# 审查代码变更

确认被审查的 PR、提交或工作区与比较基线。PR 使用目标分支的共同祖先，提交核对相应父版本，工作区按请求覆盖已暂存、未暂存和相关新增文件。目标明确时只读检查差异和受影响的调用关系。

## 从差异追到可观察后果

- 对照请求、有效契约和改前行为，找出哪些入口、数据格式、失败路径或副作用发生了变化。追到真实生产者和消费者，包括动态注册、生成源、持久化、升级恢复和外部依赖。删除字段时应能说明哪个读者、哪个支持版本或哪类数据实际受影响。
- 检查变更在什么输入和顺序下生效。异步结果、取消、资源释放、权限和数据隔离按实例与身份核对；重试有副作用时追踪原结果。保护机制已有其他有效实现时沿路径确认，避免将被保护的反例列为缺陷。
- 用差异行、可达调用链、断言或最小复现支持发现。既有问题要有该变更引入、暴露或加重影响的依据。验证缺口应说明哪个已变更的行为可能回归，以及现有断言为何观察不到。排版倾向和推测性的风险不单列为缺陷。

先给按影响排序的发现。每项指明文件和具体位置、触发条件、实际后果与判断依据，需要时给出最小修正方向。

材料缺少调用方或运行证据时单列待核实问题。没有可证实的发现就如实说明，并列出已运行的检查和未覆盖的关键路径。另有实现授权时再修改代码。
