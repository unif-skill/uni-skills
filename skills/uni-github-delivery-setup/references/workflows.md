# 工作流与验证范围

保留工程实际需要的事件、最小权限、并发控制、必需检查名称和原生构建入口。自带 RN 模板覆盖源码、库构建、原生宿主、文档站及发布；现有工作流有项目差异时先核对，不能借同步引入另一套构建或跳过行为。

## 仓内执行

CI 从当前 checkout 运行 `.github/scripts/check-delivery.cjs`。共享 PR 审查使用本仓 `.github/workflows/pr-agent-reusable.yml`，调用入口与实现一起生成、一起升级。

新项目不默认启用外部模型审查。采用自带 PR Agent 模板时，使用现有 `DEEPSEEK_API_KEY` 契约；该服务、模型与密钥需由项目明确采用。模板同步和语法测试不触发实际模型服务。

## 原有保护

- checkout 后先核对采用文件与工作流依赖；模板漂移、缺文件或已停用自动化使检查失败。
- 路径分类失败必须阻断后续判定，不能把失败等同于“无变化”。包的运行字段与纯脚本变更分别分类。
- 缓存仅加速下载或编译，命中后仍执行不可变安装与必要工具链准备。
- 已采用 PR 验证复用的工程，保持完整 Git tree、成功 attempt、所需检查与产物回执匹配；其他工程不因迁移标准而新增复用流程。
- 工作流按平台使用实际 `.github/ci/android.sh`、`ios.sh` 或现有 example 构建入口；原生源码与依赖原生能力分开判断。

工作流 YAML、actionlint、ShellCheck、模拟脚本、实际 GitHub CI 和真机验证分别提供证据。只迁移工程文件时无需重跑无关业务用例；运行远端 CI 前核对事件是否同时触发发布或外部服务。
