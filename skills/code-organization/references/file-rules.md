# 文件角色与命名

先按[平台与工具边界](platforms.md)确定语言和框架。本表的 .ts/.tsx 示例适用于手工维护的 TypeScript 源码；其他语言、单文件组件和原生资源采用各自有效格式。已有项目明确要求其他文件名时沿用其规则；工具配置、路由约定、环境声明和生成文件保留各自要求。规则用于本次新增与受影响单元，不触发全仓格式迁移。

## 文件角色

| 内容 | 默认位置 | 判断方式 |
|---|---|---|
| 显式接口、类型别名、联合类型及组件 props | 所属单元 `types.ts` | 手写对象结构用 interface；可推导内容保留推导 |
| 命名固定值、枚举值集合、码表、固定映射与默认值 | 所属单元 `constants.ts` | 不依赖本次调用、当前实例、用户或运行资源 |
| 可独立维护的样式及主题定义 | 所属单元的样式文件；RN 示例为 `styles.ts` | 运行期参数由调用处传入，主题值使用现有设计系统 |
| 具名组件 | 与组件同名的实现文件；扩展名按框架 | 私有子组件留父单元内，不因拆文件而公开 |
| hook | `useXxx.ts`，含 JSX 时 `.tsx` | React hook 采用此命名；其他框架封装按其约定归属 |
| 普通操作与辅助逻辑 | 按实际用途命名的 `.ts` | 不为分类额外增加 helper 类或服务包装 |
| 可执行 Schema | 所属单元 schema 或已有生成入口 | 只在契约需要校验时采用，不为凑文件引入框架 |
| 跨文件共享的可变状态或资源 | 所属功能的 state、store 或资源实现 | 有明确读写者、初始化及释放责任 |
| 私有局部变量 | 原函数、组件或 hook 内 | 保持调用或实例作用域，不创建 variables.ts |

类型、常量和样式随可独立维护的组件或功能归属。存在对应内容才创建 `types.ts`、`constants.ts`、`styles.ts`；分类目录不汇总各子单元的配套文件。普通工具只有实现时可保持单文件，需要独立配套内容时再形成单元目录。

以下为 TypeScript / JSX 组件单元示例：

```text
MeasurementCard/
├── MeasurementCard.tsx   # 组件及其局部生命周期
├── types.ts             # props 等显式类型
├── constants.ts         # 有业务含义的固定高亮阈值
├── styles.ts            # 基础与高亮样式
└── index.ts             # 确需跨单元消费的具名出口
```

组件没有命名固定值时省略 constants.ts；不需要目录公共入口时也无需 index.ts。简单辅助函数不各自形成目录。

## 常量与类型

`const` 只约束重新赋值。计算结果、选中项、ref、Map、SDK 实例、计时器和请求控制器是逻辑值或运行资源，保持原作用域。将它们提升至模块常量会改变实例间的共享关系。

具有业务、配置或复用展示含义的固定值使用命名常量；长度为零的判断、循环递增等直接表达。配置入口如 env.ts 仍按配置用途维护。

TypeScript 手写对象结构在 types.ts 中使用 interface，扩展用 extends；type 用于基本别名、字面量集合、接口联合或必要推导。其他语言及 ArkTS 按目标编译器支持的类型系统表达，不照搬 TypeScript 推导语法。第三方公开类型直接引用，外部字段保持协议名称。

Schema 或生成器已有权威来源时，types.ts 仅引用、派生或导出需要的类型，不复制字段。生成文件修改源后重新生成；不为文件风格引入第二份契约。

## 命名与公共入口

| 对象 | 默认约定 |
|---|---|
| 组件、组件目录、接口、类型、类 | PascalCase；组件主文件同名，接口不加 I 前缀 |
| 普通功能目录、函数、变量及主实现文件 | lowerCamelCase，以用途命名，如 imagePicker、formatDate |
| hook | use + PascalCase 主体，文件同名 |
| 命名固定常量 | UPPER_SNAKE_CASE；对象成员遵守自身语义或外部协议 |
| 事件回调 | on + 动作；请求和已完成结果在名称中区分 |
| 测试文件 | 被测单元或行为名 + .test.ts / .test.tsx |
| 平台实现 | 使用实际构建器的解析约定；RN 的 .native/.ios/.android/.web 后缀见平台专题 |

函数名与副作用一致：查询、准备、确认、提交和保存分别表达。重命名同步实际消费者，不更改协议标识或业务语义。平台差异存在时才新增对应实现文件。

跨单元使用公开文件或小型 index.ts，只导出消费者需要的接口。内部相对导入保留；私有类型和辅助函数不自动进入公共出口。避免导出所有平台、组件和业务的大型 barrel。`import type` 同样遵守模块边界。
