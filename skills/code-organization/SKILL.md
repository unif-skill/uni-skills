# 代码组织规范

按职责组织目录、文件和公开入口，保留语言、框架及构建工具的实际差异。项目已明确采用的约定优先；新增内容沿用有效规则，不因整理文件改变运行行为或重排无关代码。

## 按任务读取

| 当前工作 | 资料 |
|---|---|
| 新增功能、确定目录或共享代码归属 | [目录与职责](references/structure.md) |
| 拆分文件、类型、常量、样式、命名或导出 | [文件角色与命名](references/file-rules.md) |
| 涉及框架固定入口、生成文件或平台差异 | [平台与工具边界](references/platforms.md) |

本目录包含完整组织规则，可独立使用。具体框架实现和业务契约从目标项目取得，不要求安装其他技能。

## 新增与调整

先核对本次需求、所属单元、已有能力、实际调用方与对应检查。新增内容优先放在拥有该职责的单元中；存在明确公共职责和真实使用者时才增加共享入口。

文件名称说明内容用途，类型、固定值、样式与运行资源按语义归属。工具约定名称、生成源和语言限制在分类前确认，不能根据某个文件出现 const、interface 或样式就决定搬移。

拆分和迁移保持默认值、错误、副作用、权限、并发及资源生命周期。私有子单元仍然私有，局部变量不提升为全局共享状态。同步真实调用、导出、类型、配置和文档，清理确认无消费者的替代实现。

## 验证

使用现有编译器、lint、导入分析和相关测试，检查改动及实际消费者。固定值的业务含义、状态归属和副作用由需求及契约判断，自动检查不能替代这些判断。

除静态导入外，核对路由、动态注册、生成器、资源与平台解析等入口。新增单元具备可用入口和真实接线后，按实际影响验证关键行为；文件存在或编译成功不等于功能验收完成。
