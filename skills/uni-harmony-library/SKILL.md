# 创建和维护原生 HarmonyOS HAR 库

以 HarmonyOS API 26 为基线，先确认要交付源模块、实际 HAR、原生示例或发布版本。沿消费者的公开导入定位 Index、依赖、资源及宿主配置，按相应交付物选择验证。

## 按任务读取

| 当前工作 | 资料 |
|---|---|
| 新库、应用抽库、公共入口、依赖、共享源码或打包发布 | [库生命周期](references/lifecycle.md) |
| ArkUI 示例宿主、公开消费和文档预览 | [运行示例](references/examples.md) |
| ArkTS／ArkUI 源码、组件状态与宿主生命周期 | 按需选用 `uni-harmony-dev`，库工程流程仍由本技能承接 |

源码实现、文档与 GitHub 交付从工程维护入口取得有效约定。

## 确定并验证交付物

1. **核对工程。** 从包清单、构建配置、导出、脚本和 CI 确认 API 26 SDK、Hvigor、OHPM 和采用记录。库与示例的新 UI 均使用 V2。目标环境不支持基线时说明差异，按已批准范围处理。
2. **确认公开契约。** 核对输入、默认行为、错误、取消和资源所有权。根据库实际解析的依赖检查官方扩展点。排障时核实修复已进入可用的发行包，再更新对应导出、文档、示例与消费者。
3. **验证交付物。** 打开实际 HAR 检查包内容和公开入口，将它装入独立原生工程，运行示例并验证传递依赖和宿主配置。分别说明源码、产物和宿主结果。需要发布时另行核对目标、版本及外部操作授权。

局部维护沿用现有工程和发布流程。新建项目没有指定模板时，按真实依赖选工程方式，不预设企业包名、提供方、注册表、CI 或网站框架。原生 HAR 采用原生工具链，模板只提供起始结构。API 26 和 V2 的任务不增加旧 API 或 V1 兼容流程。
