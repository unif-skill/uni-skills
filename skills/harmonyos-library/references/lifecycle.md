# HAR 库生命周期

## 职责与公共入口

先确认可复用能力、真实消费者与所属责任。库提供自身公开能力，应用负责业务身份、导航、请求流程及必要配置；不将应用私有状态、凭据或完整业务流程随抽库迁入。新增公共包需有实际消费者和独立维护责任。

使用项目工具要求的源码、资源与固定入口；公共表面由包清单和实际导出共同确定，不因文件位于源码目录就成为 API。仅导出消费者需要的能力、类型和资源入口，类型引用也不能依赖私有深路径。包内模块按本库边界访问，跨包消费者从公开入口导入。

SDK Context、原生句柄与平台类型留在所属平台边界。宿主提供生命周期或环境依赖时，明确取得、有效期和释放责任；库不保存应用私有实例作为全局默认值。

## 依赖、资源与共享源

检查实际使用的代码、资源、原生二进制和传递依赖，说明哪些随产物交付、哪些由消费工程声明或配置。宿主权限、模块配置、SDK 支持和服务初始化按库的真实要求记录，不能只在作者的示例工程里隐式满足。

共享源码先检查完整运行与类型依赖图，包括框架装饰器、平台类型、Node／浏览器全局、原生模块及副作用。没有 import、采用 `.ts` 后缀或 Node 测试通过均不足以证明目标兼容；符合目标互操作约束的普通 TS 无须为统一后缀重写。

共同逻辑和 SVG／设计数据保持明确的单一来源，按实际目标生成或构建产物，核对源修订、生成规则与资源映射。生成文件不手改，不复制另一平台私有实现作为长期来源。共享源码不等于共享运行期状态；不为少量函数另造通用引擎或强制新增发布包。

## 打包与消费验证

从工程确认真实构建命令与 HAR 输出，检查归档内公开入口、代码、资源、声明和依赖是否与本次版本一致。用独立的原生消费宿主接入这份实际产物，从公开入口使用本次涉及的能力；消费环境不能依赖作者工作区的别名、未打包文件或私有源码路径。

源模块示例支持开发联调，但不能替代分发验证。HAR 本身不是可独立安装的应用；需要真实应用宿主生成可运行产物。空宿主构建只证明对应接线可编译，不证明权限、硬件、SDK 回执和资源释放正确。共享逻辑分别验证每个实际采用目标，不能用一个目标的测试代替其他端。

工具与产物依据见[华为 HAR 工程说明](https://developer.huawei.com/consumer/cn/doc/doccenter-deveco-studio/ide-hmos-har)；包内容与消费方式以采用版本、实际归档和宿主验证为准。

## 发布

沿用工程既定的包名、注册表、身份、版本和发布流程。查询失败或超时不证明版本不存在；重新读取远端状态后决定是否继续，不能盲目覆盖或重复发布。下载实际发布版本，核对标识、内容与已验证产物，再验证公开消费。

源码、构建、产物、宿主运行、注册表发布和网站状态分别报告；未执行的设备、权限与业务场景明确保留。包发布成功不自动证明网站已更新或用户业务已验收。
