# GitHub 工程交付

接续交付先核对最新确认的目标、排除项、已撤回方案和未完成步骤，再读目标工程的 AGENTS、manifest、Git remote、工作流及发布配置，确定本次入口、采用标准和实际授权。

已有项目沿用实际工具和发布约定。自带模板适用于明确采用 Yarn、Turbo、release-it 的 RN 库；按是否有原生源码、文档站和既有服务选择配置。其他技术栈使用其已有构建与交付入口，不套用 RN 模板。代码、平台和业务契约从目标工程取得。

RN 新工程默认使用 ESLint、Prettier、严格 TypeScript 和 Husky／lint-staged／commitlint。采用时同步本地提交检查与 CI 全量门禁，检查范围和例外写入项目入口。已有钩子先核对真实消费者与原有检查，不并装两套管理器，也不在替换时丢失分支、原生或提交保护。

## 单一来源与采用版本

采用自带 RN 工具时，将所属组织提供的规则与非敏感值落实到 `.github/organization.json`，并保留实际工作流、检查脚本及 `.github/delivery.json` 采用记录。CI 只运行仓库内已提交的工具，无需安装技能或读取技能仓；更新标准时从本技能同步，审查差异并按工程流程采用。检查记录只证明采用版本的一致性，不证明已使用最新标准。

现有工作流和工具满足要求时沿用；职责一致且能合理补足时扩展，无法合理满足时在授权内替换。共享问题在本技能来源修复后同步消费者，项目专有差异保留在所属配置。替换后核对事件、必需检查和采用记录，清理确认失效的接线与配置。保留未受管内容，局部任务不重新接入工程。

## 操作与证据

先核对修改范围和命令副作用。同步、Git 提交、远端设置、发布和部署分别按授权执行；不能因读取本技能自动启用服务、改可见性、申请权限或发布。发布查询失败不能当作版本未占用，主版本变更须有明确授权。

新仓与完整接入按[完成检查](references/adoption.md#新仓与完整接入的完成检查)分别报告本地、远端和 CI 状态；产物与消费者、发布、网站及设备结果按本次范围另行报告，不以一层结果替代其他层的验证。
