# GitHub 工程交付

先读目标工程的 AGENTS、manifest、Git remote、工作流及发布配置，确定本次入口、采用标准和实际授权。本技能可独立使用，不要求安装或调用其他技能。

## 按任务读取

| 任务 | 资料 |
|---|---|
| 新工程接入、模板同步、检查漂移 | [接入与同步](references/adoption.md) |
| CI 事件、验证范围、权限与 PR 审查 | [工作流](references/workflows.md) |
| 分支保护、必需检查及仓库设置 | [远端设置](references/repository.md) |
| 首次发布、常规发行或恢复验收 | [发布与恢复](references/release.md) |

已有项目沿用实际工具和发布约定。自带模板适用于明确采用 Yarn、Turbo、release-it 的 RN 库；按是否有原生源码、文档站和既有服务选择配置。其他技术栈使用其已有构建与交付入口，不套用 RN 模板。代码、平台和业务契约从目标工程取得。

## 单一来源与采用版本

通用机制和共享工具在本技能目录维护；企业规则及非敏感值由所属组织维护，接入时落实到工程 `.github/organization.json`。消费仓保存实际工作流、检查脚本及 `.github/delivery.json` 采用记录。CI 只运行仓库内已提交的工具，无需安装技能或读取技能仓；标准更新通过同步和工程正常 PR 流程生效。检查记录表示采用版本的一致性，不证明正在使用最新标准。

在技能来源修复共享问题，再同步实际消费者；保留项目自有配置和未受管内容。缺少技能安装不影响已接入工程运行 CI；已有资料覆盖当前任务时直接使用，不重复启动工程接入。

## 操作与证据

先核对修改范围和命令副作用。同步、Git 提交、远端设置、发布和部署分别按授权执行；不能因读取本技能自动启用服务、改可见性、申请权限或发布。发布查询失败不能当作版本未占用，主版本变更须有明确授权。

交付分别报告工作树、源码检查、实际 tarball 与消费者、CI、发布、网站及设备结果。模板或本地检查通过不表示远端保护已启用，也不表示包或网站已发布。
