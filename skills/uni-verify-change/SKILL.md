# 验证已有变更

确定待验差异的起点、终点和运行对象。记录版本或工作区状态，沿修改行找到实际入口、直接消费者以及相关配置、生成产物和资源。先写清每个受影响行为的成功、失败或保护条件，再选能观察该条件的检查。

| 差异涉及 | 选择的检查及判据 |
|---|---|
| 局部实现或等价重构 | 运行相关静态检查与实际调用方用例，对照正常和边界输入的返回、事件顺序及副作用。 |
| 已定位的缺陷 | 在相同触发条件下对照修复前后的结果，保留正常对照。身份切换、迟到回执和重试使用可控事件驱动。 |
| 类型、协议、存储或导出 | 核对生产者和消费者，按同一生成源重建并检查差异。按支持范围验证旧数据恢复、输入接受或拒绝及当前消费者可观察的结果。 |
| 构建、配置、安装或部署内容 | 核对修订、产物、目标环境和加载方式。验证运行实例实际使用相关配置或产物；按验收范围继续核对启动、真实宿主、设备或业务结果。 |
| 展示或交互 | 从实际界面入口执行可比条件下的操作，核对呈现、状态和提交结果。平台差异按受影响平台选择宿主。 |

从项目维护入口、脚本、CI 或锁文件找到正式命令，使用对应解释器、依赖和配置。先运行最能判定目标行为的检查，再补依赖架构或项目门禁要求的范围。Python 项目按采用的类型检查器和配置执行；工具启动失败时核对解释器、依赖与工作目录，修正后重跑。部署、重跑远端 CI 或真实外部写入需要各自的操作授权。

将实际运行的命令、环境、观察结果对应到差异。静态检查、自动化、构建、安装、启动与业务验证只各自证明其观察到的事实。先前结果只在修订、内容、配置及环境仍适用时复用。遇到失败说明失败层级、原因及缺失证据。交付结论列出已证实的行为和待验证部分，指出依赖的最小补查条件。
