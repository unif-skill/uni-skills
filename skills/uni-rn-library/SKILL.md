# React Native 库工程

以库的公开能力、真实消费者和项目采用的工程标准为依据。源码维护、开发接入、公开发行和实际发布是不同范围，按当前任务推进。

## 按任务读取

| 当前工作 | 资料 |
|---|---|
| 新库默认开发规范，或升级类型、lint、格式与提交检查 | [默认开发检查](references/quality.md)；保留库声明生成、构建及打包入口 |
| 新库、应用抽库、原生依赖、打包或发布 | [库生命周期](references/lifecycle.md) |
| 可运行示例或 example 接线 | [运行示例](references/examples.md) |
| 源码目录、文件命名与公开出口 | 按本库规范执行；需要通用组织规则时可选用 `uni-code-organization` |
| RN 组件、Hook 与平台实现 | 可选用 `uni-rn-dev`，本库契约仍来自项目 |
| 文档、文档站及其生成与构建 | 按本库文档要求执行；可选用 `uni-documentation` |

## 工程依据

接续任务先核对最新确认的能力与交付范围、排除项及已撤回方案，再读目标库的 AGENTS、开发资料、manifest、脚本和相关 CI，定位项目明确采用的模板或组织标准。交付配置以本库实际工作流、检查脚本和采用记录为准；外部标准用于明确授权的更新，本地未提交草稿与已采用版本分别识别。

封装前核对公开扩展点是否已满足需求。排障以消费者实际解析的 npm 包和原生 SDK 版本核实上游修复，补丁随包或由宿主提供的条件见[依赖与补丁](references/lifecycle.md#依赖与补丁)。

项目未指定统一模板时，采用默认开发检查，构建、打包和发布按当前库的真实依赖与消费者需要选择；不假定存在特定企业、包名、CI 服务、发布机器人或文档框架。工程已接入且任务只改组件时，复用有效依据，不重新初始化或配置发布。

## 维护与验证

公开输入、默认值、错误、取消、平台支持和资源责任按当前契约核对。公开类型从同一代码源导出；文档、示例和消费者跟随实际接口更新。内部复用不自动扩大 npm 公共表面，库不读取应用私有路由、store 或环境配置。

按本次影响验证源码、公开类型、实际 tarball、消费者及必要原生场景；文档交付条件按项目要求核对，站点工作由文档任务承担。测试替身、站点或库内 workspace 导入通过，不能代替独立消费和设备行为；各层结果分别说明。

发布按本次授权与项目既定流程执行；只读查询失败不证明版本可用。目标、前置与发布后验收见[发布与恢复](references/lifecycle.md#发布与恢复)。
