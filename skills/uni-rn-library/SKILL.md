# React Native 库工程

以库的公开能力、真实消费者和项目采用的工程标准为依据。源码维护、开发接入、公开发行和实际发布是不同范围，按当前任务推进。

## 按任务读取

| 当前工作 | 资料 |
|---|---|
| 新库、应用抽库、原生依赖、打包或发布 | [库生命周期](references/lifecycle.md) |
| 可运行示例或 example 接线 | [运行示例](references/examples.md) |
| 源码目录、文件命名与公开出口 | 按本库规范执行；需要通用组织规则时可选用 `uni-code-organization` |
| RN 组件、Hook 与平台实现 | 可选用 `uni-rn-dev`，本库契约仍来自项目 |
| 文档、文档站及其生成与构建 | 按本库文档要求执行；可选用 `uni-documentation` |

本技能的库工程规则与资料完整保存在本目录，可独立安装使用；其他技能是可选组合，不是运行前置。

## 工程依据

先读目标库的 AGENTS、开发资料、manifest、脚本和相关 CI，定位项目明确采用的模板或组织标准。交付配置以本库实际工作流、检查脚本和采用记录为准；外部标准用于明确授权的更新，本地未提交草稿与已采用版本分别识别。

项目未指定统一模板时，按当前库的真实依赖和构建需要选择工程方式；不假定存在特定企业、包名、CI 服务、发布机器人或文档框架。工程已接入且任务只改组件时，复用有效依据，不重新初始化或配置发布。

## 维护与验证

公开输入、默认值、错误、取消、平台支持和资源责任按当前契约核对。公开类型从同一代码源导出；文档、示例和消费者跟随实际接口更新。内部复用不自动扩大 npm 公共表面，库不读取应用私有路由、store 或环境配置。

按本次影响验证源码、公开类型、实际 tarball、消费者及必要原生场景；文档交付条件按项目要求核对，站点工作由文档任务承担。测试替身、站点或库内 workspace 导入通过，不能代替独立消费和设备行为；各层结果分别说明。

发布使用项目既定流程，并核对目标包、版本历史、授权及实际远端前置。只读查询失败不证明版本可用；操作完成后验证 registry、下载产物与网站各自状态。
