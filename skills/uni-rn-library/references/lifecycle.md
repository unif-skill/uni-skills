# 库生命周期

## 创建与提取

先从真实消费入口、状态归属和依赖核对已有库或组件。满足目标平台和公开契约时直接复用；职责一致且能合理补足时扩展；无法合理满足时，按授权提取、替换或新增。模板选择依据实际需要维护的源码：

| 实际实现 | 工程方式 |
|---|---|
| TS/TSX 调用现有原生 SDK | 使用适合的 JS/TS 库工程，声明 SDK 与宿主要求，不创建空壳原生桥 |
| 库维护自己的原生模块或视图 | 按实际 Native Module、视图和平台构建要求采用对应模板 |

没有自有原生源码的库也可能需要真实 iOS/Android 宿主；选择 JS 模板不能删除项目已要求的原生验证入口。[运行示例](examples.md#原生接入)说明宿主配置与预览平台的适用条件。模板 CLI 的选项从当前安装版本或官方资料核对。

从应用提取时记录来源与已授权的入口、依赖、状态和生命周期，保留默认值、结果、错误、取消、并发与文件责任。为脱离应用进行必要参数化，调用方传回原值；目录调整不改变业务行为。已有计划、设计和必要验收记录继续保留。

凭证、服务地址和业务路径按明确接口由使用方提供，公开源码、示例与包产物使用非敏感配置。迁移完成后核对全部相关消费者、公开导出与宿主接线，清理确认无消费者的旧实现及失效配置。

## 工程接入

项目标准的内容与入口从采用来源读取，按当前阶段选择：

| 阶段 | 核对内容 |
|---|---|
| 开发接入 | 模板、脚本、类型、测试和 CI 是否实际接线 |
| 公开发行准备 | 包身份、公开出口、许可、README、详细文档、实际打包内容及项目要求的站点 |
| 远端配置 | 必需检查注册、分支保护、发布身份和仓库或 registry 绑定 |
| 发布后验收 | 新版本记录、元数据、下载产物及文档部署结果 |

同步工具会修改文件，设置工具可能修改远端。检查参数和影响后执行已授权部分；模板问题在所属来源修复，不在单库复制一套流程。检查模式、命令名称和门禁由实际项目定义，本表不要求所有库使用同一套服务。

本地候选不因公开发行检查而提前改许可、建站、配置远端或发布。已有 website 和测试入口按本次影响维护。

## 依赖与补丁

按公开消费方式声明运行依赖和 peer，检查实际解析到的副本。区分支持范围、开发锁定版本及补丁的精确版本；一套验证组合不等于全部消费者必须采用该组合。

原应用依赖 SDK 补丁时，核对修补能力、适用版本和调用方。补丁继续由已确认的维护方管理，并按已确认的方式提供；采用宿主维护时，库文档说明取得、应用、重建和检查方式，不自行将补丁收入 tarball 或通过安装脚本修改消费者依赖。

库内 Yarn patch、patch-package 或本机 node_modules 差异不会因安装一个 TS 包而自动出现在消费应用。验证时从同一维护源准备补丁，检查库和宿主实际解析的 SDK。更换分发来源或补丁归属需要明确相应影响。

## 打包与消费者

运行已有源码检查和构建，再生成真实 tarball。核对文件清单、包身份、声明的 exports、类型入口和必要运行资源；排除私有配置。包清单检查不证明 TypeScript、Metro 或原生运行成立。

在独立目录从该 tarball 按包名和公开子路径导入，验证类型、运行入口及真实依赖；不依赖库源码别名或 workspace 软链接。需要原生 SDK 时接入相应宿主、补丁和平台配置，执行受影响的构建与行为检查。设备或服务不可用时保留独立可完成的检查，并明确证据限制。

## 发布与恢复

确认包名、scope、registry、仓库、版本和发布历史。查询超时、404 或空列表不证明版本从未占用，已发布版本不当作新版本重用；不通过试发或覆盖标签探测状态。

使用项目已有的版本与 CI 发布方式；版本、主版本升级、仓库可见性和远端操作分别按有效授权执行。合并会触发发布时，将这一后果计入授权范围。首次建立包身份或恢复中断发布，读取项目专门流程，不临时改成本机发布或新凭据方式。

发布后分别核对 registry 元数据、实际下载文件、版本记录和站点。版本已发布而验收失败时，先修复或恢复验收，不无条件再次发版。最终说明区分本地实现、提交、CI、发布、部署及设备和业务验收。
