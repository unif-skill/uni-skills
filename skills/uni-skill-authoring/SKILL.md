# 技能编写与审校

让技能在合适的任务中被选中，提供当前有效、可直接采用的指引。修改范围按本次需求确定。

## 编写与整理

1. **先查已有内容。** 核对使用场景、现有技能、相关条目和引用来源。已有规则能承接时修改或合并，有独立职责和使用场景时再新增技能。
2. **把经验整理成规则。** 写清适用条件、具体做法和验证方式；不搬入聊天过程、临时措辞或把单次修复推广到所有任务。
3. **分清适用范围。** 通用规则保留跨项目适用性，项目约定从当前工程取得。核实阶段要求是否仍有效，过期内容移出现行指引，必要历史依据保留原语境。
4. **保留有效约束。** 精简重复说明时，对照需求和契约保留权限、身份、平台、错误、取消、并发和资源责任。发现冲突先核实来源，不凭文字长短或实现现状改变规则。
5. **正文直接指导任务。** 说明需要读取什么、采用哪个入口、如何判断和验证。执行所需的来源、版本和限制留在对应步骤。面向使用者的插件安装放在接入文档，维护分工和生成流程放在维护入口。

## 触发与资料

`description` 写清任务场景和必要的排除范围，执行步骤放正文。技能名称、展示摘要和默认提示与实际用途一致；自动选用策略按用户要求配置，不因整理文字改变调用方式。

已有通用技能承接的任务保留一个可调用入口。专项写明何时选用该技能，保留本平台或场景特有的判据。独立安装不要求把通用技能正文复制到专项资料或换名注册。专项自身必读的协议、模板等资料仍可按正式分发机制从同一源生成并校验一致性。

## 完成检查

对照差异检查新增内容是否重复、过期要求是否仍有入口、有效约束是否丢失。核对描述、元数据、引用、生成副本及实际受影响消费者，运行适用的格式和一致性检查。

新增或调整触发范围时检查应选与不应选的任务；规则变化用实际材料核对输出与行为。格式通过、模型选对名称、实际读取技能和完成任务分别记录，不把未执行的验证写成通过。
