# 文档站

负责文档站的信息组织、导航、页面展示、文档生成、构建与页面检查。使用项目已采用的框架、样式和发布约定，不为普通文档维护重新选型或重做站点。

## 内容与来源

从开发资料、网站配置、同类页面和实际构建脚本确认框架、导航、样式及文档来源。正式使用文档、开发调试页和产品运行示例分别提供明确入口。

README、接入指南、API 与开发资料按[文档类型](content-types.md)分工。共享内容维护一个来源，通过链接或既有生成链使用；API、LLM 索引与全文按当前公开类型、注释或 Markdown 生成，不手改输出或重复维护接口。

页面与包描述使用一致的概念，保留实际支持范围。调整分组、标题或路径时核对现有导航、锚点及真实引用，优先保持对外地址稳定。

## 页面与预览

沿用项目已有组件和样式。用途、示例、参数与必要限制层次清楚；窄屏可收缩或换行，图片保持比例，滚动限制在合适区域。只因文案修改，不增加无关控件或重排产品交互。

需要展示交互时，先确定读者运行的平台，再使用真实公开示例。预览、必要状态控件与结果区分开，详细诊断按需展开；用法代码对应实际演示。

运行示例由所属产品或库工程维护，文档站提供展示和入口。网页、截图、iframe 或模拟数据明确各自展示范围；原生平台的设备能力需要真实宿主验证，静态网站不要求为原生库增加浏览器实现或替换 SDK。

前端组件预览按实际版本接入主题、字体、安全区或弹层等必要宿主，核对静态生成、客户端加载和交互。参考网站的 alias、shim 与依赖只在本项目确有需要时采用，不直接复制整套环境。

## 生成与构建

修改实际源文件后执行相关生成、类型、链接及构建检查，审查产物差异；不要用全量生成掩盖无关接口或版本漂移。核对 CI 是否覆盖被网站使用的文档、源码、类型和生成输入，保留项目已有工程门禁。

在真实页面检查桌面与窄屏、已支持主题、导航、锚点和刷新；交互预览补事件、状态、键盘与控制台检查。界面文案变化在可比条件下核对前后效果。

分别报告文档生成、类型与构建、页面操作和产品示例运行结果。网站构建不证明页面可用或线上已更新；部署仅按任务授权与项目流程执行。
