# 第三方技术接入

先核对适用版本的官方推荐用法与最佳实践，再结合项目有效契约和实际消费者确定方案。

## 确认依据

承接方案时先核对最新已确认的选型、排除项和已撤回意见，再从依赖声明、锁文件及实际安装或构建产物确定采用版本、平台和宿主约束；尚未采用的能力明确候选版本。沿真实调用检查项目已有接入及消费者，再查阅适用的官方文档、示例、最佳实践和限制，核对初始化、状态与资源归属、并发、错误和取消等实际涉及的语义。

读取相关原文并确认版本范围，不能仅凭搜索摘要、最新首页示例或同名 API 判断当前版本支持。同一上下文中已核对、仍适用且覆盖本次判断的资料可复用；版本、平台或问题条件变化时补查差异。

排障先保留复现条件，检查实际调用与配置，再核查官方故障说明、issue／PR、发布记录和迁移指南。对应问题、修复提交与发行版本，确认修复已进入可取得的包且适用于当前环境；issue 关闭、PR 合并或上游单测通过不等于修复已发布，也不证明本项目已恢复。

官方资料不足或不可访问时明确缺口，可结合采用版本的公开类型、源码和本地复现继续核实；社区资料作为线索，不代替官方支持或发布证据。不能将未查到解释为没有方案，也不能据此猜测升级版本。

## 选择方案

| 当前依据 | 采用方式 |
|---|---|
| 官方支持的配置、公开接口或扩展机制已满足有效契约 | 优先使用现有能力，保持项目自身的状态、身份和资源责任；不重复实现 SDK 已承担的流程 |
| 已发布版本包含适用修复或必要能力 | 核对兼容性、迁移成本、宿主与消费者影响，再在授权内升级；不因版本更新而升级 |
| 官方能力仍有已确认缺口，或适用修复尚不可采用 | 优先扩展职责一致的现有接入或采用必要补丁；无法合理满足时，在授权内替换或新增。说明缺口、与官方建议的差异、维护归属及退出条件 |

自有库封装围绕稳定的公开能力与真实语义差异，不复制第三方内部状态或用额外包装隐藏接入错误。官方推荐方案与项目契约冲突时说明适用差异，不直接改写既有行为；新增服务、权限、部署依赖或扩大升级范围按当前授权处理。

## 验证与交付

关键决策给出官方来源、适用版本、选择原因及未确认项，详细程度与变更影响相称。排障保留原复现并核对修复前后行为；设计与开发验证真实接入、必要边界及实际消费者，涉及宿主或原生变化时补相应构建与运行验证。

源码核查、自动化、构建、设备或真实业务结果分别说明。第三方发布说明和上游测试只能证明其对应范围，不能代替项目验证。补丁替换或移除前核实发布修复、实际采用版本与消费者；替换后迁移调用并清理失效补丁、配置或重复实现，保留仍有依据的兼容和保护。
