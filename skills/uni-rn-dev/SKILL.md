# 开发与调试 React Native 功能

从用户实际操作的页面或库入口确认所改行为、React/RN 版本和目标平台。定位 props、Hook、原生调用与组件卸载各自的责任，再选择对应实现或真机调试步骤。

## 按任务读取

| 当前工作 | 资料 |
|---|---|
| 新工程、默认开发规范、ESLint／TypeScript／格式或提交检查接入，以及变更前核对现有门禁 | [默认开发检查](references/quality.md)及其配置模板 |
| 组件、Hook、受控交互、主题和样式 | [组件与状态](references/components.md) |
| 平台适配、原生依赖、宿主与验证 | [平台接入](references/platform-integration.md) |
| iOS 实体设备安装、当前 JS 核实、Metro 或自动化连接恢复 | [iOS 安装与调试](references/ios-device-debugging.md) |

目录、文件和工程命令从项目维护入口及配置取得。组件内部逻辑在真实父组件中核对输入、事件和状态；变更原生接线时还需检查目标平台的宿主。

日常维护执行项目已采用的检查；新工程或门禁升级采用表中的默认开发检查，保留仍有效的例外。

## 修改与验证

按有效需求和既有接口确定要改的行为。沿页面或调用入口找到现有组件、SDK 和状态所有者，确认实际缺口。将组件展示、应用组合及原生能力各自的改动留在对应位置。

接入 npm 包或原生 SDK 时，按应用实际解析的版本核对官方接口与限制。排障核对修复是否进入宿主可用的发行包，分别验证受影响的平台。依赖选型和补丁取舍可选用 `uni-third-party-integration`。

UI、默认值、事件、错误、取消、权限和资源语义随有效契约保持。替换后迁移相关消费者，清理确认失效的实现、导出和接线。修改后检查组件、实际使用场景与必要宿主；类型、自动化、构建、页面或设备与业务验收分别报告。
