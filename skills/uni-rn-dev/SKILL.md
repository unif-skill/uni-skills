# React Native 开发规范

按当前 React/RN 版本、项目契约和实际平台实现功能，保持组件状态、调用与资源的正确归属。

## 按任务读取

| 当前工作 | 资料 |
|---|---|
| 组件、Hook、受控交互、主题和样式 | [组件与状态](references/components.md) |
| 平台适配、原生依赖、宿主与验证 | [平台接入](references/platform-integration.md) |
| iOS 实体设备安装、当前 JS 核实、Metro 或自动化连接恢复 | [iOS 安装与调试](references/ios-device-debugging.md) |

本目录包含完整 RN 实现指引，可独立使用。目录与文件按项目有效约定组织；需要通用组织规则时可选用 `uni-code-organization`，库工程可选用 `uni-rn-library`，文档任务可选用 `uni-documentation`。它们不是安装前置。

## 实施

先核对本次入口、已有组件或 SDK、公开接口和实际消费者。组件、应用组合与原生能力承担各自已确认的职责；先用现有公开能力实现，缺口由所属实现补齐。

涉及第三方库、框架或 SDK 时，先按实际采用版本核对官方推荐用法与限制；排障同时确认修复是否已发布及适用，再决定配置、升级或自有修复。详细核查可选用 `uni-third-party-integration`，不是前置依赖。不能把架构候选当成已发布 API，也不因“更新”改变依赖、默认行为或支持范围。平台和设备差异保持明确。

UI、默认值、事件、错误、取消、权限和资源语义随有效契约保持。修改后检查组件、实际使用场景与必要宿主；类型、自动化、构建、页面或设备与业务验收分别报告。

函数职责与异步流程重构可选用 `uni-code-organization`，源码契约注释可选用 `uni-documentation`；这些通用规则不替代本平台生命周期和实际调用验证。按采用版本与本次场景选用已有 React／RN 等专项指引，不复制整套规则或设为安装前置。
