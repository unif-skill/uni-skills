# 平台接入与验证

## 依赖与宿主

核对当前公开 SDK、实际版本、依赖声明和使用场景。已有组件、Hook、操作与类型直接使用，自有适配承接真实语义差异、宿主参数或资源处理。

主题、字体、手势、安全区和弹层宿主按公开接口组装；原生依赖的自动链接、权限、初始化、Pods/Gradle 及补丁按项目配置。原生配置变化需对应重建，JS 热更新不能证明原生接线更新。

配置和凭证从明确来源传入，公共组件与库不读取应用私有账号、路由或整份业务 store。已有日志与失败处理继续有效，避免复制运行时或在页面重复接入同一设备流程。

## 平台差异

根据真实差异使用平台分支或平台文件，按 Metro 和项目配置核对解析。共享入口表达支持范围，不把成功 Mock 当正式平台实现。

RN Web、iOS 和 Android 分别验证所需环境。没有 Web 实现的原生库可提供文档或原生示例，不为浏览器演示擅自更换 SDK；Expo Go 是否可运行由实际内置模块和版本决定。

本技能不提供 ArkUI 实现规范。同名原生鸿蒙库、相似类型或无框架导入不能证明 RN 接口可迁移；跨端行为按共同契约对齐，语法和接线分别处理。

## 验证

使用项目当前的类型、lint、组件和逻辑测试，验证被修改的真实实现与事件。外部依赖可以替换，被测状态、映射与交互不换成自证成功的替身。

组件检查受控值、事件、默认值、错误及必要 UI 状态；宿主和异步流程检查多实例、切换、取消、卸载和迟到结果。原生依赖变化另检查构建及设备行为，浏览器或模拟器不能替代未覆盖的硬件场景。

测试、构建和现场参数来自实际工程。保留有效检查与断言，报告本次平台和场景覆盖，不把类型或截图检查写成设备或真实业务验收。

依据：[React Native 平台文件](https://reactnative.dev/docs/platform-specific-code)。
